# SessionRelay 记忆台 · 前端设计说明 (DESIGN.md)

> 面向场景：开发者每天开工前或遇到卡壳时，扫一眼「我的记忆库现在什么状态」，偶尔调旋钮、按维护动作。

---

## 1. 选了哪条方向

### 定位：高密度遥测机架（Telemetry Console）
我们选择将记忆台设计为**专业级开发者记忆遥测台**，而非通用的“SaaS 管理后台”或“表单填报页”。

- **视觉基调**：深石墨色机架质感（自适应 DSH 宿主环境 CSS 变量，深色为底、低光发射、高对比度可读性）。
- **信息架构**：
  - **顶部 HUD 脉搏**：一眼看清守护在线状态、心跳延时、总对话量、有效结论、待决问题、已归档正文、可注入经验与总占用。
  - **五大视角（1-5 键直达）**：
    1. **总览 (`1`)**：项目库活跃度矩阵 + 生命周期流水线阶段看板 + 语义检索增强档位。
    2. **经验 (`2`)**：跨项目经验池透析，准入率漏斗，定级/状态双轴筛选，一键复制经验。
    3. **压缩 (`3`)**：L0~L3 五层架构透视表，L0 去重度量，L2 归档老化雷达（连续强度阶梯分布图与不动原因榜）。
    4. **旋钮 (`4`)**：28 个系统旋钮分 7 组管控，标注生效来源（ENV / 项目定制 / 默认），浮动修改暂存条与一键写回。
    5. **动作 (`5`)**：5 项白名单命令，只读演练 vs 真写真跑（双重写入安全锁），自带微终端输出与复制。

## 2. 为什么选这个方向

1. **让数字讲故事**：
   - 记忆库的核心价值不是“查看一条聊天记录”，而是“系统帮我沉淀了多少决策”、“有多少经验真的能进新对话”、“压缩到底省了多少空间”。
   - 将 `dupCount`、`cleanup_log`、`aging.strengthBuckets` 用比例条和柱状阶梯直观展现，比枯燥的数据表更具洞察力。
2. **键盘流与极速操作**：
   - 开发者手不离键盘：支持 `1-5` 快捷键切页、`R` 键即时重拉数据、输入框和按钮均有清晰的高对比度 `:focus-visible` 轮廓。
3. **零认知负担的安全性**：
   - 动作执行采用“安全锁（写入锁）”机制：会写库的命令（sync, recompute, compact, clean）在未勾选锁时直接禁用，杜绝误触毁库。

## 3. 放弃了什么（品味减法与反 AI 痕迹）

依据 `ai-design-workflow` 与 `deliver.md` 的指引，我们在设计中坚决做了减法：

1. **放弃了无脑的霓虹发光与毛玻璃（No Glow / No Glassmorphism）**：
   - 剔除任何背景光晕、进度条荧光、无功能的渐变色。
2. **放弃了一模一样的 SaaS 卡片套装与软阴影（No Cookie-Cutter SaaS Cards）**：
   - 不搞大面积软阴影（`rgba(0,0,0,0.1)`），不用千篇一律的卡片套模板，采用清晰利落的边框分割与层级明确的机架面板。
3. **放弃了模板化装饰字眼**：
   - 不搞全大写字母拉开字距的无意义 eyebrow 标签；
   - 不用 `A · B · C` 连串占位；
   - 按钮后不无脑加 `→`；
   - 界面全中文优先，人话表述（如“正文已蒸发·结论保留”、“准入率”、“活力分”）。
4. **放弃了沉重的第三方图表库（Chart.js / ECharts / D3）**：
   - 硬约束要求零 npm 依赖；我们使用原生 HTML + CSS 灵活绘制了准入比率条、项目占比条、会话连续强度阶梯图，渲染性能在 1ms 内，完全零包袱。
5. **放弃了花哨过渡动效**：
   - 开发者高频使用的面板，最忌讳动效阻塞或眩晕。仅保留 80~120ms 的必要几何反馈，并严格配置 `@media (prefers-reduced-motion: reduce)` 适配。

## 4. 接口契约取舍

1. **保持宿主端零破坏升级**：
   - 现有 9 个方法（`overview`, `compression`, `config`, `applyConfig`, `lessons`, `lifecycle`, `actions`, `run`, `diagnostics`）语义清晰、逻辑完备，全部沿用并补全了完整的响应封套契约文档。
2. **铁律 22 的彻底执行**：
   - 无论在总览、经验还是压缩页，底部都设有「专业统计口径抽屉」，将内核 `PANEL_CRITERIA` 逐条摆出，确保所有数字来源清晰可核查。
3. **前端不越权**：
   - 前端一行 SQL、一个写死阈值都没有。即使经验准入的逻辑很直观，也绝不在前端手写 `live >= 0.7`，而是严格读取后端计算好的 `item.injectable` 与 `data.threshold`。

## 4. 第二轮：配色改版（2026-10-17 夜，用户令「配色什么的改改」）

### 问题
第一版用的是 GitHub 暗色**逐字**同一套（#0d1117 / #161b22 / #30363d / #388bfd / #3fb950 / #f85149）——
任何人一眼就认成「又一个 GitHub 克隆」。这正是 ai-design-workflow 说的最典型的 AI 味来源：
**不是难看，是没有自己的东西。**

### 动作
按 skill 的规矩，可查数据不凭空想 —— 实际跑了参考库：
ui-ux-pro-max/scripts/search.py "dark dashboard developer tool color system" --design-system，
它给 OLED 暗色档：底 #0F172A、卡 #1B2336、副 #334155、前景 #F8FAFC、强调 #22C55E。

### 三条判断（写下来，免得下次又被顺手改回 GitHub 色）
1. **换底**：slate 系（#0F172A 底 / #1B2336 卡 / #242E45 浮层 / #334155 边）。
   底色仍留 var(--dsh-*) 天窗，DSH 宿主切浅色主题时跟着走。
2. **强调色不能是绿**：参考库给的是 #22C55E 绿，但**本面板里绿色已经是判据色**
   （守护在线 / 可注入 / 达标）。强调色和判据色抢同一语义，人分不清「这是按钮还是状态灯」。
   所以交互强调色选 **sky 天蓝 #38BDF8**，绿只留给状态。
3. **语义色重新落位**（深灰底上要更亮才够对比）：
   正常 #22C55E / 注意 #F59E0B / 否决 #F43F5E / 信息 #38BDF8 / 定级 #A78BFA。

### 顺手做的减法
项目行里原本每个项目挂一枚绿胶囊「守护在线」——**八行同色噪音**，信息量只有 1 bit，
却占了最大的视觉重量。改成 **7px 状态点**（绿=在线 / 琥珀=离线，语义用 title 与 aria-label 保留），
文字留给真正出问题的那一行（红胶囊）。

### 验收
- selftest.mjs（全量，含一次真 CLI 动作）**46 项全绿**；
- 真浏览器渲染 + Playwright 截图比对（改前 / 改后）；
- 源码里已无 GitHub 旧色残留（两个硬编码色也改成了变量）。

## 5. 第三轮：瑞士国际主义 × 编辑杂志网格重构（2026-10-17 用户令）

### 用户原话与核心痛点
> 「那个设计的面板，花里胡哨的，我也看不清楚到底在哪里点。」
> 方向拍板：从「精工仪器台（深色机架）」改为「瑞士国际主义 × 编辑杂志网格」，并修掉 4 个真实缺陷。

### 设计决策（严格遵循 ai-design-workflow 循环）

#### 1. Discover（品味引导与喜欢/讨厌记录）
- **讨厌（负向品味）**：
  - 深色机架的沉闷压抑与微弱变色的 hover 暗示（导致可点击区域看不清在哪里点）；
  - 滥用毛玻璃（Glassmorphism）、微弱发光（Glow）、装饰性渐变；
  - 死板对称、缺乏节奏感的一模一样 SaaS 卡片和软阴影。
- **喜欢（正向品味）**：
  - 瑞士国际主义：黑白单色骨架、单一交互强调色、直角（0px border-radius）、零软阴影；
  - 编辑杂志网格：非对称流动栅格、正文衬线体、大字重无衬线标题、刊头规则双线、首字下沉（Drop cap 4em）、引言块（Blockquote 1.5em）、间距与栏距 2rem；
  - 实体点击触点一眼可辨：清晰边框、反色反白悬停、明显的高对比度焦点环。

#### 2. Define（设计系统规范与减法取舍）
- **骨架规范**：
  - 容器直角化：全界面统一 `--sr-radius: 0px !important`；
  - 阴影清零：`--sr-shadow: none !important`；
  - 实体按钮：`border: 1.5px solid var(--sr-border)`，悬停时触发高对比度**黑白反转**，点击区域一目了然；
  - 强调色克制：仅保留单一强调色（跟随 DSH `--dsw-alias-interactive-primary`），其余一律采用黑白灰对比；
  - 动效克制：纯几何与状态反馈控制在 200ms 以内，完备支持 `@media (prefers-reduced-motion: reduce)`。
- **杂志排版**：
  - 刊头双线规则：Heavy line (3px) + Light line (1px)；
  - 大留白节奏：区块留白 2rem ~ 2.5rem，告别局促拥挤；
  - 响应式栅格：大屏 12 列非对称，中屏/窄屏流体单列折叠，废弃写死固定像素宽度。

#### 3. Deliver（4 个缺陷实测根因与修复）

1. **缺陷 1：L3 模型压缩 9 个旋钮在面板不显示**
   - **实测根因**：面板 `KNOB_GROUPS` 仅硬编码 7 组，漏掉了 `compress` 组。导致 `compress.enabled`、`provider` 等 9 个旋钮被过滤。
   - **修复与防复发**：
     - 补齐 `compress` 组，并改用从后端返回的全部 knobs 动态归类兜底机制；
     - 在 `selftest.mjs` 中添加防复发断言，从核心清单 `KNOB_SPECS` 提取全部 8 组前缀，严格断言客户端分组定义完整覆盖全部前缀。

2. **缺陷 2：面板关闭重开后，鼠标滚轮失效无法上下滚动**
   - **实测根因**：DSH 宿主外层容器 `.BynINW_centerCol` 设置了 `overflow: hidden; height: 100%`。之前面板 `.srelay-root` 仅设置 `min-height: 100%`，并未将其自身声明为独立的滚动视口（Scrollport）。面板关闭重开重新挂载后，因不是滚动容器，鼠标滚轮事件向上冒泡至宿主父容器，被 `overflow: hidden` 直接吃掉，造成滚轮彻底失效。（经实测排查，原怀疑的 `fixed inset:0` 遮罩层在 client.js 源码中并不存在，纯属子容器未自设 `overflow-y: auto; height: 100%` 所致）。
   - **修复**：将 `.srelay-root` 定义为标准滚动容器：`box-sizing: border-box; height: 100%; width: 100%; overflow-y: auto; overflow-x: hidden; scrollbar-gutter: stable;`，彻底根治滚轮失效。

3. **缺陷 3：切换页签时偶尔出现整块空白**
   - **实测根因**：
     - `CompressionView`、`SettingsView` 等子视图在数据未到位（`!data`）时直接渲染为 `null`，无任何骨架或 Loading 占位；
     - `useApi` 在 Tab 切换（`enabled: false -> true`）时滞后于组件的初始 render，第一帧渲染跳过 `loading && !data`，误将 `data: null` 当作空数据呈现，造成瞬时整片空白。
   - **修复**：在 `useApi` 中优化状态保持机制，切走时不销毁已有有效数据；为所有子视图提供统一的杂志排版风格骨架加载屏（`SectionLoading`），消灭任何 `null` 空白态。

4. **缺陷 4：面板尺寸与桌面端窗口不匹配，打开时突兀**
   - **实测根因**：原样式中有多处固定写死的像素宽度（如 `maxWidth: 1200` 居中、`width: 220`、`width: 280`），缺少 `@media` 响应式断点，窄屏或分屏时发生截断与换行重叠。
   - **修复**：改用 `clamp(1.5rem, 3vw, 3rem)`、`fr` 等相对单位与流动弹性栅格，配置 `@media (max-width: 900px)` 自动折叠为单列杂志排版，完美适配各类桌面窗口尺寸。

### 二、连线审计四项结论
1. **旋钮覆盖（Knobs Coverage）**：

   - `lib/client.js:1113` 的 `dynamicPrefixes` 逻辑严格从接口返回的 `knobs` 动态推导前缀，前端全部 5 种控件类型完整绑定至 `draft`，保存时走 `applyConfig` 接口完整写回。
   - **结论：全部 8 组 39 个旋钮均能正常展示与修改写回。**
2. **宿主接口覆盖（Host Methods Coverage）**：
   - `lib/index.js:140-217` 定义的 9 个接口中，7 个核心交互接口前端均有对应调用点；`lifecycle` 已内嵌在 `overview` 中被前端消费，`diagnostics` 为自检/外呼接口。前端无调用任何不存在的宿主方法。
3. **死控件（Dead Controls）**：
   - 全面板无任何故障或无响应死控件。梳理出 14 处纯前端状态/剪贴板本地控件（如规则抽屉展开、内存筛选输入、保护锁勾选、复制等），行为均与设计意图吻合。
4. **死数据（Dead Data）**：
