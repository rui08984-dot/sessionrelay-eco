# 工程笔记：我们踩过的坑（以及为什么代码长这样）

> 每一节都是**实测**结论，不是设计推演。公开发布这些，是因为其中多数坑
> 任何做"本地记忆层"的人都会遇到——包括最阴的那种：**全绿着的坏**。

## 一、静默半失效：自检全绿，功能全无

**症状**：插件装了、命令成功、库建好了、`doctor` 22 项 0 失败、自测全 PASS——
而你的会话**永远采不进来，全程零报错**。

**成因（实测三类）**：
1. **新文件没进加载路径**：pnpm 的 `file:@依赖走硬链接，**原地改的老文件会同步，新增文件不会**。
   一个新增的 `brief-filters.mjs` 没进 `.pnpm` 副本 ⇒ 插件整体加载失败，而所有自检都对。
2. **常驻进程跑的是旧代码**：文件更新了，进程没重启。守门脚本从此新增"进程启动时间 vs 最新构建时间"这一段。
3. **上游包被静默使用**：适配器解析到的是**上游版** CLI（没有本项目修复），简报是脏的，但一切正常。

**对策**：验收必须跑**真实链路**（真的调用一次、真的看输出），而不是"文件存在/字符串存在"。
本项目的守门脚本对外只报**可执行**的检查结论。

## 二、用探测脚本验"结构"，会被结构骗

早期用"文件里有没有某个字符串"来验构建产物，结果假绿（打包器把单引号规范成了双引号）；
后来改成"必须真的 `import` 一次并调用"。**探针必须 import 生产实现**，不能复刻逻辑。

## 三、中文检索的取舍

- 分词器两套（jieba / bigram），**索引与查询必须同一套**，否则搜不到。
- **关键词命中 20/20，大白话命中 top-1 仅 10/20**。我们做了 20 问基准（`tools/ses-recall-probe.mjs`）来盯这件事，
  而不是靠"感觉还能用"。
- 三个改善方向：① 本地小模型嵌入（撞"不做神经路线"）② 同义词表（零模型但要人养）③ 接受边界。
  **目前选 ③，并把短板写在 README 里。**

## 四、被实测否掉的方案（别再走一遍）

| 方案 | 实测结果 |
|---|---|
| 按角色过滤决策 | 74.9% / 48% 的决策来自助手侧，属正常对话而非子任务 ⇒ 过滤会误杀 |
| 自动推翻过时决策 | 87% / 53% 误配；即便只用来源最干净的子集仍有 92% 误配 |
| 环境事实抽取 | 全库 0 条真事实 |
| 断点胶囊（自动生成续作摘要） | 可用率 35% |
| 六维抽取器升级 | 三类通道全是助手自述/任务书/粘贴件 ⇒ 等于把病因复制六份 |
| 跨项目联邦 | 7 个库 0 条置顶 ⇒ 规则输出恒为空 |
| 两阶段语义检索 | 当时用三个查询判"问题不存在"——**下得太快**，20 问基准显示概念型问法确实弱，已改标"待重测" |

## 五、一条被反复验证的纪律

> **数字必须绑定快照与口径**：写 `28/908 @ 22:45 @ 全库口径`，
> 否则数据在动，任何人复核都得不到同一个数。

同理：**负结果必须落盘**。这份笔记里最长的一张表就是负结果表——
它比成功清单更省后来人的时间。
