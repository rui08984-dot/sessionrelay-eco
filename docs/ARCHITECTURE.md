## 六个决定性设计

**1. 一个项目一个库，物理隔离**
`<项目>/.sessionrelay/relay.sqlite`。不做全局库、不做跨项目联邦。
隐私边界 = 文件边界：删目录即彻底消失，不需要"忘记我"的功能。

**2. 零神经网络**
提取靠规则（8 层防线），检索靠 SQLite FTS5 + 中文分词。没有 embedding、没有外部 API。
代价写在明处：**换词命中弱**（见 [ENGINEERING-NOTES.md](ENGINEERING-NOTES.md)）。语义档是显式 opt-in 的可选增强。

**3. 提取规则带版本号，且存量的每个会话自报版本**
`EXTRACT_VERSION` 递增 ⇒ 只重算**落后的**那些会话。没有这个，
要么全库重算（贵），要么规则改了存量永远是脏的（静默）。

**4. 简报是"取数"，不是"写死"**
DSH 插件在**每个模型步骤前**现查一次库；ZCode hook 在 SessionStart 查一次。
两者共用同一套过滤规则（同一份 `brief-filters.mjs`，两侧一致性由守门脚本对拍）。

**5. 多副本一致性当作一等公民**
同一份代码存在多个加载路径（作者副本 / 各 profile / `.pnpm` 硬链接副本）。
`tools/check-versions.mjs` 九段逐份 md5 对拍——因为**历史上真的出现过"作者副本是新的、加载副本停在昨天"**。

**6. 常驻进程不会自己变新**
改完文件必须说清"哪个进程需要重启"。守门脚本会明确报出"守护进程启动时间早于最新构建"。

## 数据流（一次会话）

```
你在项目里干活
   ↓
适配器把会话写进 <项目>/.sessionrelay/relay.sqlite（守护/插件，旁路）
   ↓
提取器按规则抽出 决策 / 未决问题 / 涉及文件 / 话题
   ↓
下次开场：简报取数（看板 2 行 + 决策 4 条 + 最近在动 3 个文件）
   ↓
模型带着这些上下文开口 ——「注入≠强制续作，你下一句话才是指令」
```
